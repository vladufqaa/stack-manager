# История изменений

Все заметные изменения Stack Manager собраны в этом файле.

## [Нереализовано]

### Изменено

- Завершён вывод автопочинки по таймеру из архитектуры: удалены мёртвые `inbounds_need_heal()`, `heal_once()`, `install_heal_timer()` (~85 строк). `uninstall_heal_timer()` сохранён — дочищает остатки старых юнитов при установке/переустановке.
- Диагностика и аудит больше не проверяют `stack-heal.timer`: `[!] stack-heal.timer: не active` исчез из «Полного аудита» и раздела сервисов; секция «Heal-таймер» заменена на честную «Самолечение / защита БД» (проверка защиты БД сохранена).

### Исправлено

- «Статус» больше не вываливает содержимое `/root/panel-credentials.txt` и `/root/adguard-credentials.txt`: это снимки пароля на момент установки, они дублировали URL выше и вводили в заблуждение после смены пароля. Теперь показываются путь к файлу и дата снимка.
- Блок AdGuard в «Статусе»: если сервис установлен, но не активен, печатается предупреждение вместо URL, по которому отдавался бы 502.
- Исправлена запись `adguard-credentials.txt` при смене пароля: вместо литеральной заглушки `<домен панели>` подставляется живой домен из конфигурации панели; при неизвестном домене строки URL не пишутся вовсе.

## [1.0.21] — 2026-10-26

### Исправлено

- Исправлен недостижимый дефолт SNI-домена для обычного VLESS TCP: вторая ветка `vless` в `case` никогда не выполнялась, и мастеру создания инбаунда показывался чужой домен по умолчанию (`h.example.com` вместо `r.example.com`).
- Исправлено дублирование слеша в URL панели в шапке меню при `webBasePath` с завершающим слешем (получалось `https://example.com/path//`).

### Изменено

- Удалён мёртвый код: неиспользуемая шапка-«бокс» (`menu_header`, `svc_dot`, ~45 строк с python-хердоком) и недостижимый дублирующий `pause` в меню decoy-шаблонов.
- Точечные чистки по shellcheck: поясняющие директивы для переменных, которые задаёт `askyn` косвенно; явное `: >` при очистке лога decoy-попыток; убран лишний `$(echo …)` вокруг prompt в TUI файрвола; массив пакетов вместо непроверяемого split в переустановке nginx.
- Пункт 5 DNS-меню переименован под фактическое поведение v1.0.20: домен Self-hosted DoH берётся из SNI-конфигурации AdGuard, а не из домена панели.
- Добавлен CI: на каждый push в main и PR выполняются `bash -n` и `shellcheck` (принятые исключения — в `.shellcheckrc`).
- Из эксплуатации выведена веб-диагностика stack-web: служба `stack-web.service` остановлена и удалена, nginx-маршрут `/stack/` снят; приложение сохранено в бэкапе на сервере.

## [1.0.20] — 2026-10-22

### Исправлено

- Self-hosted DNS Xray (профиль 5) теперь определяет фактический внешний домен AdGuard Home из SNI-конфигурации nginx (`agh_backend`), а не безусловно использует домен панели.
- Для отдельного домена AdGuard используется, например, `https://adguard.example.com/dns-query`; для размещения за панелью сохраняется домен панели.
- Если внешний домен AdGuard не найден в SNI/nginx-конфигурации, операция безопасно прекращается — неверный endpoint не записывается в `xrayTemplateConfig`.

## [1.0.19] — 2026-10-22

### Исправлено

- Для профиля 6 «Свой DoH» добавлена строгая смысловая проверка IPv4 (каждый октет 0–255), hostname и совпадения host с URL.
- Перед изменением панели выполняется реальный DoH-запрос к `example.com`: проверяется HTTPS-ответ, DNS-флаг ответа, отсутствие ошибки RCODE и наличие записей.
- Self-hosted и пользовательский DoH теперь не принимаются только по форме ввода: нерабочий endpoint блокирует изменение Xray.
- Проверка выполняется до остановки `x-ui` и записи `xrayTemplateConfig`, поэтому ошибочный ввод не оставляет панель в промежуточном состоянии.

## [1.0.18] — 2026-10-22

### Добавлено

- Добавлена безопасная первичная инициализация `xrayTemplateConfig` из рабочего `/usr/local/x-ui/bin/config.json`, если шаблон ещё не создан панелью.
- Добавлена проверка обязательных outbound `direct`/`blocked` и `routing.rules` перед созданием шаблона.
- Добавлен backup базы перед инициализацией и автоматический rollback при ошибке.
- После перезапуска `x-ui` проверяется фактическое наличие DNS в сгенерированном `config.json`.
- README дополнен инструкциями по DNS Xray, DoH и проверке результата.

## [1.0.17] — 2026-10-19

### Исправлено

- Перед изменением `xrayTemplateConfig` создаётся отдельная копия `x-ui.db`.
- При ошибке записи или неудачном запуске `x-ui` база автоматически восстанавливается из этой копии.
- Безопасный отказ при отсутствии шаблона сохраняется: рабочая конфигурация Xray не создаётся «с нуля».
- Отсутствующий `xrayTemplateConfig` теперь проверяется до создания backup и не запускает ложное восстановление неизменённой базы.
- В backup стека добавляется диагностический manifest итогового Xray-конфига с тегами `api`/`blackhole`, числом routing rules и SHA-256; последний manifest доступен веб-диагностике для точечного сравнения.

## [1.0.16] — 2026-10-19

### Добавлено

- Добавлено меню настройки DNS Xray в панели LucX/3x-ui через раздел «Панель и AdGuard».
- Добавлены профили системного DNS, Cloudflare DoH, Google DoH, Quad9 DoH, self-hosted DoH панели и собственного DoH.
- Для self-hosted DoH домен панели и IPv4 сервера определяются автоматически.
- Для пользовательского DoH добавлен ввод URL, host и IPv4-адреса.
- При управляемом DNS автоматически задаются `routing.domainStrategy=IPIfNonMatch`, `queryStrategy=UseIPv4` и `ForceIPv4` для direct outbound.

### Исправлено

- Исправлена ошибка с двойным обратным слешем, из-за которой Python-блок настройки DNS не запускался корректно.
- Исправлена потеря тегов `api`, `blackhole`, правил маршрутизации, outbounds и других полей при сохранении `xrayTemplateConfig`.
- Сохранена исходная обёртка `xraySetting`, используемая LucX/3x-ui.
- Удалён небезопасный fallback на минимальный шаблон при ошибке чтения существующей конфигурации.
- Добавлена безопасная остановка операции при повреждённом или неизвестном формате `xrayTemplateConfig`.
- Обновление шаблона выполняется через `UPDATE`, без предварительного удаления рабочей записи.

## [1.0.15] — 2026-10-19

### Исправлена проверка занятых портов

- Порт `443` теперь явно запрещён для inbound, поскольку используется внешним SNI/nginx-маршрутизатором.
- Для порта `80` выводится отдельное понятное сообщение о занятости ACME/nginx.
- Исправление применяется как в обычном мастере создания inbound, так и в полном автоматическом сценарии.

## [1.0.14] — 2026-10-18

### Синхронизирована отображаемая версия

- Исправлено несоответствие между `VERSION` и `STACK_MANAGER_VERSION` внутри скрипта.
- После обновления меню теперь показывает фактическую версию релиза, а не старую `v1.0.10`.
- Релиз `v1.0.13` содержал исправление сертификата, но внутренняя строка версии в скрипте не была обновлена.

## [1.0.13] — 2026-10-18

### Исправлена проверка wildcard-сертификатов

- `cert_preflight` больше не зависит от текста, который печатает OpenSSL.
- Успешный `openssl x509 -checkhost` определяется по коду возврата.
- Исправлена совместимость с OpenSSL, который пишет `does match certificate` вместо `Hostname ... was found`.
- Wildcard `*.example.com` корректно принимается для `host.example.com`, если срок и ключ действительны.

## [1.0.12] — 2026-10-18

### Исправлен аудит публичных UDP-инбаундов

- Hysteria/Hysteria2 больше не ошибочно отмечаются за внешний `listen`.
- Для Hysteria, Hysteria2, qwdtt и csqtt внешний адрес прослушивания считается допустимым.
- Проверки реального сокета и сертификата остаются без изменений.

## [1.0.11] — 2026-10-18

### Распознавание уже установленного стека

- Если старая версия уже устанавливала стек, но не создала `.stack-configured`,
  установка распознаётся по legacy-маркеру `.stack-ever-ran`, базе панели и
  основным конфигурациям nginx/SNI.
- После проверки автоматически создаётся `.stack-configured`.
- Уже установленный скриптом стек больше не попадает ошибочно в безопасный режим,
  поэтому все пункты меню открываются.

## [1.0.10] — 2026-10-18

### Безопасный режим и heal timer

- Убрана блокировка всех пунктов меню до первичной настройки.
- Read-only диагностика, просмотр сертификатов, бэкапы и проверка состояния теперь доступны без `.stack-configured`.
- Изменяющие операции остаются ручными и выполняются только из выбранного пункта меню.
- `stack-heal.timer` можно оставить включённым: до явной настройки `heal_once` ничего не делает.
- После успешной первичной настройки создаётся `/root/stack-backups/.stack-configured`, и автоматическое обслуживание включается.
