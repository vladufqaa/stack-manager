# История изменений

Все заметные изменения Stack Manager собраны в этом файле.

## [Нереализовано] — накопитель до следующего релиза

### Добавлено

- Режим `--status`: разовая read-only проверка здоровья стека без меню (`bash stack-manager.sh --status`) — тот же набор, что в самодиагностике: службы, порты, `nginx -t`, сертификаты, UFW, fail2ban, живые ответы decoy-страниц, слушающие порты инбаундов, диск/бэкапы, DNS-привязка доменов. Exit-код 1 при проблемах — можно вешать на cron и внешние проверки.
- П.8→3 «Распаковка архива переезда»: после распаковки проверяется целостность x-ui.db (`PRAGMA integrity_check`) и сверяется число инбаундов/клиентов со снимком до распаковки; при битой БД или меньшем количестве данных — предупреждение с путями к снимку, автоматического восстановления нет.
- П.8→3 «Распаковка архива переезда»: умное включение UFW после распаковки. Архив возвращает конфиги (`user.rules`, `ENABLED=yes`), но фильтрацию в ядре никто не включает — firewall оставался выключенным (это показала проверка на 109 после полного отката). Теперь UFW включается автоматически, если в архиве он был включён, ещё не активен и в правилах есть allow для текущего SSH-порта (порт берётся из `SSH_CONNECTION` и слушающих сокетов sshd); если allow нет — предупреждение с готовой командой вместо включения, сессию не отрезает.
- Новый раздел меню 8 «🚚 Переезд на другой сервер»: полный перенос стека на новый хост при банах/смене IP. Порядок жёсткий — сначала на новом сервере поднимается платформа из скрипта (пакеты, nginx, панель, базовый UFW), только потом распаковывается архив со старого. Пункты: 1) экспорт (архив БД/nginx/сертов/декоев/бота + sha256), 2) установка платформы, 3) распаковка со сверкой sha256, 4) проверка привязки каждого домена к новому IP, 5) перевыпуск сертификатов (обычный/принудительный/выборочный), 6) проверка после переезда (службы, серты decoy), 7) чек-лист. Архив создаётся с остановкой x-ui и checkpoint WAL, копится в `/root/stack-backups/migrate-*.tar.gz` с правами 600, домены собираются из БД, SNI-карты, renewal и CDN-профилей (чужие Reality-цели исключаются).

### Исправлено

- `mk_plain_fallback_decoy`: в plain-шаблоне декоа для Xray-fallback `try_files` записывался как `\\$uri` внутри неотэкранированного heredoc — bash съедал `$`, и nginx получал `try_files \ \/` с ошибкой 500 «internal redirection cycle» на каждом запросе к заглушке.
- `stack_del_decoy` игнорировал маркеры `# >>> fallback-plain` — повторные запуски плодили дубли plain-блоков того же домена, а nginx обслуживал всегда первый (битый). Добавлен второй параметр `decoy|fallback-plain|all`; upsert в `mk_plain_fallback_decoy` теперь реально чистит старый блок. `stack_del_all_decoy` тоже удаляет оба типа.
- П.8→3 «Распаковка архива переезда»: проверка читаемости архива всегда падала с «Архив не читается» на целых архивах. Причина: под глобальным `pipefail` конструкция `tlist=$(tar tzf … | head -5)` давала `tar` SIGPIPE (head закрывает пайп после 5 строк, tar получает 141 при записи следующих блоков) — подстановка считалась упавшей и `|| tlist=""` затирал результат. Список теперь берётся целиком без пайпа, первые 5 строк показываются через herestring. Проверено на архиве 538 записей: `gzip -t`/`tar tzf` — 0, repro с pipefail давал пустой список.
- П.8→3 «Распаковка архива переезда»: после распаковки убирается дистрибутивный `sites-enabled/default` — пакет nginx при переустановке возвращает symlink, а `stack.conf` тоже объявляет `default_server` на :80; из-за дубликата `nginx -t` падал («a duplicate default server for 0.0.0.0:80»), и nginx оставался остановлен. Если есть `streams-available/sni-router.conf`, но нет ссылки в `streams-enabled` — она восстанавливается (раньше строка была no-op `|| true`).
- Выровнен plain-шаблон fallback-декоа с ssl-шаблоном: в plain не было ловушек сканеров — `wp-login.php`, `.env`, `admin`, `wp-admin`, `.git`, `phpmyadmin` и др. отдавали 200 (контент страницы) вместо 404, и не было правила `/login` (`limit_except POST` → 403). Теперь оба шаблона отвечают одинаково: `/` 200, ловушки 404, `/login` 403. Проверено на 109: ssl-декои (rx 4447, h 47007) и plain (rt 47003) отдают идентичные коды.

## [1.0.35] — 2026-11-01

### Изменено

- tg-stack-bot, отказоустойчивость («бот обрывается»): юнит переведён с `Restart=on-failure` на `Restart=always` + `RestartSec=3` + `StartLimitIntervalSec=0` — теперь systemd поднимает бота и после чистого выхода (деплой-стоп, exit 0 без токена), и после падения, без упора в rate-limit; при установке и включении бота старый юнит мигрирует автоматически (бэкап в `/root/stack-backups/tg-stack-bot.unit.pre-always-*`). Проверено на живом сервере: юнит активен, журнал чистый, кнопки отвечают.

  установка распознаётся по legacy-маркеру `.stack-ever-ran`, базе панели и
  основным конфигурациям nginx/SNI.
- После проверки автоматически создаётся `.stack-configured`.
- Уже установленный скриптом стек больше не попадает ошибочно в безопасный режим,
  поэтому все пункты меню открываются.

## [1.0.10] — 2026-10-18

### Безопасный режим и heal timer

- Убрана блокировка всех пунктов меню до первичной настройки.
- Read-only диагностика, просмотр сертификатов, бэкапы и проверка состояния теперь доступны без `.stack-configured`.
- Изменяющие операции остаются ручными и выполняются только из выбранного пункта меню.
- `stack-heal.timer` можно оставить включённым: до явной настройки `heal_once` ничего не делает.
- После успешной первичной настройки создаётся `/root/stack-backups/.stack-configured`, и автоматическое обслуживание включается.
