# История изменений

Все заметные изменения Stack Manager собраны в этом файле.

## [Нереализовано] — накопитель до следующего релиза

## [1.0.30] — 2026-10-30

### Добавлено

- Пункт 6 в меню «🤖 TG-бот» (п.7 → TG-бот): «🔑 Токен бота и ID владельца» — просмотр (токен маскируется, показываются первые цифры и последние 4 символа), ввод и смена `BOT_TOKEN`/`ADMIN_CHAT_ID` в `/root/.tg-stack-bot.env` (EnvironmentFile юнита tg-stack-bot). Токен перед сохранением проверяется живым `getMe` через тот же TG-выход, что использует бот (state `/root/.tg-stack-bot-out.env`: outbound → локальный socks, socks → свой URL, direct → напрямую); при отказе Telegram или недоступности сети — явный вопрос «сохранить всё равно». ID владельца валидируется числом; перед записью предлагается тестовое `sendMessage` владельцу (подсказка про /start при «chat not found»). Запись атомарная (tmp + mv), права 600, чужие строки и комментарии файла сохраняются, старый файл бэкапится в `/root/stack-backups` как `tg-bot-env.pre-creds-<ts>`. Так как env юнита читается только при старте, после записи предлагается рестарт tg-stack-bot с проверкой активности и журналом при падении.
- Тестовое сообщение владельцу при включении бота: п.5 «🟢 Включить бота» после успешного старта автоматически шлёт `sendMessage` на `ADMIN_CHAT_ID` через `BOT_TOKEN` из env юнита (тем же TG-выходом, что и бот). Если токен/ID не заданы — подсказка настроить их в п.6; при неудаче доставки — описание ошибки от Telegram и напоминание про /start. Неудачная отправка не мешает результату включения бота.

## [1.0.29] — 2026-10-30

### Добавлено

- Пункт 5 в меню «🤖 TG-бот» (п.7 → TG-бот): включение/выключение самого бота одной кнопкой. Если бот запущен — «🔴 Выключить (stop + disable)», если нет — «🟢 Включить (start + enable)»; состояние услуги tg-stack-bot проверяется при каждом входе в меню, поэтому подпись пункта всегда актуальна. При неудаче старта (юнит упал сразу) показываются последние строки journalctl; state `/root/.tg-stack-bot-out.env` тумблером не трогается — режим TG-выхода переживает выключение. Технически: блок TG-бота перенесён из собранного артефакта в модуль `src/195-botout.sh` (правило «правки только в src/» восстановлено).

## [1.0.28] — 2026-10-30

### Изменено

- Управление «TG-выход» бота (tg-stack-bot) перенесено из Telegram-меню в SSH-меню stack-manager.sh (п.7 «Панель и AdGuard» → «🤖 TG-бот: выход в Telegram»). В боте остался только статус выхода на карточке сервера; меню «📤 TG-выход» и все связанные шаги (свой SOCKS, JSON аутбаунда, отключение) удалены. Логика без изменений: state `/root/.tg-stack-bot-out.env`, хирургия `xrayTemplateConfig` (socks-инбаунд tgbot-in на 127.0.0.1:<порт> + правило роутинга), бэкап config.json/БД перед правкой, включение только после живой проверки 204, откат при неудаче. Бот теперь сам подхватывает смену режима на лету по mtime state-файла — рестарт бота после переключения не нужен.

## [1.0.27] — 2026-10-29

### Добавлено

- Инбаунды AmneziaWG 3.1 и 2.0 (LucX sidecar, Premium-профиль) в мастере создания: transport awg31/awg20 с корректными именами «AmneziaWG 3.1/2.0» (раньше awg падал в fallback «Awg» без версии; флаги обфускации и settings-JSON не тронуты). UFW-правило открывается с комментарием «AmneziaWG awg<id>» вместо безымянного. AWG-аудит встроен в полный аудит (stack_full_audit), шаг awg_repair — в «⚡ Проверить всё и починить» (проверено на живом сервере: ISSUES 2→0, повторный прогон идемпотентен; детекция UFW-правила заанкорена на начало строки).
- Модель hosts «один хост»: все TCP-инбаунды (кроме CDN-профилей) получают hosts-строки общей группы group_id, п.6.1 чинит hosts таких групп. Имя новой общей группы — «443» (внешний вход стека), а не имя первого инбаунда; существующие группы наследуют своё имя, CDN-хосты (remark «CDN_<протокол>») не затрагиваются. Аудит не считает отсутствие hosts-строки проблемой, восстановление сертов и проверка SNI больше не пересоздают hosts (в том числе не поднимают строки из hosts_shadow).
- cert_fresh_cover: cert_issue_line пропускает выпуск, если линию уже покрывает свежий (старше 30 дней — как «ещё живой») wildcard/SAN-серт; при покрытии wildcard восстанавливается флаг WILDCARD_STATE. Батч больше не плодит персональные серты поверх wildcard (история 28.10: 7 лишних выпусков из старого реестра линий).

### Изменено

- «⚡ Проверить всё и починить»: сходимость сокетов — 2 стабильных прохода с дедлайном 90 с вместо долгих ожиданий, живой прогресс без блокировки stdin (прогон не «зависает» до нажатия Enter), честный счётчик дельты «было → осталось», awg/wireguard/amnezia исключены из loopback-ложных срабатываний. Разгадан флап сокетов: LucX пересоздаёт inbound-обработчики через xray API — контрольный рестарт x-ui поднимает «мёртвые» порты.
- Сокет-аудит: ретраи 8×2 с вместо 3×2 с — медленный старт отдельных портов (37039/11443) больше не даёт ложных «сокет не слушает».
- Креды панели (логин/пароль/порт/путь/подписки) собираются ДО установки на любом пути — первый запуск и переустановка используют один и тот же ask_panel_creds; установщик LucX получает порт/путь через env (XUI_PANEL_PORT/XUI_WEB_BASE_PATH), панель больше не живёт пол-установки на случайном адресе; ask_panel_creds при уже установленной панели не затирает собранные значения, preset пароля без БД не перегенерируется.
- Из мастера создания инбаундов убран пункт «VLESS XHTTP TLS» (XHTTP доступен как REALITY и через CDN); из диагностики убран отдельный пункт «AmneziaWG-статус» — дублирует полный аудит.

### Исправлено

- Погашены EOF-петли интерактивных вопросов класса «валидация → continue → EOF возвращает тот же дефолт»: ask/askyn не крутятся на исчерпанном файле автоответов (было ~90 000 ошибок/мин), decoy_template_choose_impl принимает имя шаблона (EOF-дефолт вне списка заменяется глобальным), ask_sni_domain на не-TTY сам подбирает свободный SNI-домен, домен- и порт-циклы мастера инбаундов — 3-страйк с пропуском инбаунда (плейсхолдер r.example.com больше не даёт вечный цикл), не-TTY initial_setup берёт ответы из глобальных мастера (устранён каскад «не распознан/EOF»). Восстановлен вопрос VK call hashes для qwdtt/csqtt (терялся — vk оставался пустым).

## [1.0.26] — 2026-10-27

### Исправлено

- Определение панели LucX на свежей установке. `detect_panel_flavor` опиралась только на маркеры в БД (триггеры `lucx_shareonly_*`, таблица `client_inbounds`, sidecar-теги), которых на свежей LucX-установке может ещё не быть: триггеры/таблицы создаются миграциями панели, а `sqlite3` при первом запуске скрипта ещё не установлен (ensure_deps выполняется только после явной настройки). В обоих случаях мастер создания инбаундов показывал «оригинальный 3x-ui», не предлагал QWDTT/CSQTT/tproxy/naive/anytls/trusttunnel и отправлял в миграцию п.7, которая в этой ситуации ничего не меняла. Теперь после проверки БД функция смотрит на саму установку: строка «lucx» в бинарнике панели (путь из ExecStart юнита x-ui, по умолчанию `/usr/local/x-ui/x-ui`) и в менеджер-скрипте `x-ui.sh` — у оригинального 3x-ui таких строк нет. Проверка не зависит от sqlite3. Добавлен регрессионный тест `work/check-flavor-unit.sh` (8 сценариев: БД-маркеры, вердикт 3x-ui, свежая LucX по бинарнику/x-ui.sh, sqlite3 недоступен, нет БД).

## [1.0.25] — 2026-10-26

### Исправлено

- Восстановлены две функции, удалённые ранее при живых вызовах. `ask_sni_domain` (выбор SNI-домена с проверкой занятости) была удалена в 1.0.23 как «осиротевшая», но её вызывали 6 потоков создания Reality/TLS-инбаундов — на этих путях скрипт падал «command not found». `db_set_listen` (смена listen инбаунда напрямую в БД с журналированием) не существовала с v1.0.15: вызовы в применении CDN-профиля и полном откате гасились `|| true`, поэтому listen молча не переключался, а журнал отката не пополнялся. Функция воссоздана самодостаточно: прежнее значение пишется в `inbound-listen.tsv` в формате читателя (`__NULL__`/`__EMPTY__`), первое изменение для id — приоритетное для отката. В служебный каталог разработки добавлены сканер неопределённых вызовов функций (учёт вложенных функций и heredoc) и регрессионный тест обеих функций с заглушками ask/sqlite3. Комментарий формата CDN-профиля в шапке дополнен 8-м полем provider.

## [1.0.24] — 2026-10-26

### Добавлено

- Выбор провайдера CDN в анкете CDN-профиля: **Beget**, **Yandex Cloud**, **Другой/свой**. Провайдер хранится 8-м полем профиля (старые 7-польные записи совместимы и отображаются как «не указан»), показывается в аудите CDN, мини-меню инбаунда и сводке профиля, сохраняется при всех перезаписях профиля (`cdn_repair`, смена decoy, смена профиля). Для Beget и Yandex Cloud печатаются подсказки настройки на стороне провайдера: CNAME cdn-домена на edge, origin = ORIGIN-домен по HTTPS:443, отключение кэша для пути транспорта, у Яндекса — сертификат на стороне Яндекса и Host/SNI к origin = ORIGIN. Неинтерактивно задаётся через `CDN_PRE_PROVIDER=beget|yandex|other`.

## [1.0.22] — 2026-10-26

### Добавлено

- Пункт 6-1 «⚡ Проверить всё и починить»: одним действием — полный read-only аудит, безопасная автопочинка найденного и контрольная проверка с дельтой «было → осталось». Чинит детерминированное: поднимает упавшие nginx/x-ui, синхронизирует серты/decoy инбаундов (`sync_inbound_certs`), чинит CDN-дрейф (`cdn_repair`), открывает отсутствующие UDP-правила UFW, пересобирает xray-конфиг рестартом x-ui для мёртвых сокетов. Сертификаты LE не выпускает (квоты — раздел 3) и не правит битый nginx-конфиг вслепую — только показывает причину. Перед починкой — явное подтверждение.

### Изменено

- Меню «Диагностика и обслуживание» сокращено с 8 до 6 пунктов без потери функций: «Аудит CDN и drift» удалён (полностью входит в «Полный read-only аудит»), «UDP-инбаунды и UFW» удалён (та же проверка и открытие портов уже внутри «⚡ Проверить всё и починить»). Нумерация 1–3 сохранена, полный аудит стал пунктом 4.
- Завершён вывод автопочинки по таймеру из архитектуры: удалены мёртвые `inbounds_need_heal()`, `heal_once()`, `install_heal_timer()` (~85 строк). `uninstall_heal_timer()` сохранён — дочищает остатки старых юнитов при установке/переустановке.
- Диагностика и аудит больше не проверяют `stack-heal.timer`: `[!] stack-heal.timer: не active` исчез из «Полного аудита» и раздела сервисов. Секция «Самолечение / защита БД» удалена из аудита совсем: `frozen()` и `db_protect_state()` — заглушки, раздел «Заморозка самолечения» в меню отсутствует, поэтому предупреждение не могло стать зелёным никогда и советовало несуществующий раздел.

### Исправлено

- «⚡ Проверить всё и починить»: после рестарта x-ui контрольный аудит больше не стартует через фиксированные 3 секунды — xray с Reality/туннелями поднимает сокеты дольше, и аудит ловил ложные «сокет не слушает» (выглядело как «было меньше, чем осталось»). Теперь порты опрашиваются до 30 секунд с учётом протокола; в лог пишется, через сколько каждый поднялся.
- UDP-инбаунды в «Полном аудите» (Listening ports) и в этапе 5 «⚡ Проверить и починить» проверяются сокетом `ss -u`, а не только TCP (`ss -t`): раньше здоровые hysteria/qwdtt/csqtt-порты помечались «сокет не слушает» и провоцировали лишний рестарт x-ui при каждой починке.
- «Статус» больше не вываливает содержимое `/root/panel-credentials.txt` и `/root/adguard-credentials.txt`: это снимки пароля на момент установки, они дублировали URL выше и вводили в заблуждение после смены пароля. Теперь показываются путь к файлу и дата снимка.
- Блок AdGuard в «Статусе»: если сервис установлен, но не активен, печатается предупреждение вместо URL, по которому отдавался бы 502.
- Исправлена запись `adguard-credentials.txt` при смене пароля: вместо литеральной заглушки `<домен панели>` подставляется живой домен из конфигурации панели; при неизвестном домене строки URL не пишутся вовсе.

- Self-hosted DNS Xray (профиль 5) теперь определяет фактический внешний домен AdGuard Home из SNI-конфигурации nginx (`agh_backend`), а не безусловно использует домен панели.

- При ошибке записи или неудачном запуске `x-ui` база автоматически восстанавливается из этой копии.
- Безопасный отказ при отсутствии шаблона сохраняется: рабочая конфигурация Xray не создаётся «с нуля».
- Отсутствующий `xrayTemplateConfig` теперь проверяется до создания backup и не запускает ложное восстановление неизменённой базы.
- В backup стека добавляется диагностический manifest итогового Xray-конфига с тегами `api`/`blackhole`, числом routing rules и SHA-256; последний manifest доступен веб-диагностике для точечного сравнения.

## [1.0.13] — 2026-10-18

### Исправлена проверка wildcard-сертификатов

- `cert_preflight` больше не зависит от текста, который печатает OpenSSL.
- Успешный `openssl x509 -checkhost` определяется по коду возврата.
- Исправлена совместимость с OpenSSL, который пишет `does match certificate` вместо `Hostname ... was found`.
- Wildcard `*.example.com` корректно принимается для `host.example.com`, если срок и ключ действительны.

## [1.0.11] — 2026-10-18

- Если старая версия уже устанавливала стек, но не создала `.stack-configured`,
  установка распознаётся по legacy-маркеру `.stack-ever-ran`, базе панели и
  основным конфигурациям nginx/SNI.
- После проверки автоматически создаётся `.stack-configured`.
- Уже установленный скриптом стек больше не попадает ошибочно в безопасный режим,
  поэтому все пункты меню открываются.

## [1.0.10] — 2026-10-18

### Безопасный режим и heal timer

- Убрана блокировка всех пунктов меню до первичной настройки.
- Read-only диагностика, просмотр сертификатов, бэкапы и проверка состояния теперь доступны без `.stack-configured`.
- Изменяющие операции остаются ручными и выполняются только из выбранного пункта меню.
- `stack-heal.timer` можно оставить включённым: до явной настройки `heal_once` ничего не делает.
- После успешной первичной настройки создаётся `/root/stack-backups/.stack-configured`, и автоматическое обслуживание включается.
